# 执行者简报模板（派子代理时直接套用）

> 用途：主会话派子代理做**检索 / 下载 / 归集**时，用本模板生成指令。
> 由来：同一条 Skill、同一批文献，两个执行者耗时相差 **45 分钟 : 5 分 50 秒**（1 篇 vs 10 篇）。
> 差异不在 Skill 内容，而在**指令里有没有硬预算和放弃规则**。本模板把这两样固化。

## 0. 必须先给的四件事

不写全这四条，别派活：

1. **动作序列**（第 1 步干什么、第 2 步干什么），精确到工具名与坐标/选择器；
2. **预算**（每单元最多几步、几秒、几次重试）；
3. **放弃条件**（什么现象出现就跳过、什么现象出现就整队停）；
4. **回报结构**（JSON 字段，尤其 `file + field` 定位）。

## 1. 硬预算（写进指令，不许含糊）

| 项 | 默认值 | 超了怎么办 |
|---|---|---|
| 单个条目的步数 | **≤ 6 步** | 立即标 `failed`，写清卡在第几步，进下一条 |
| 单个条目的耗时 | **≤ 90 秒** | 同上，不许"再试一次应该就好了" |
| 同一操作的失败重试 | **≤ 1 次** | 第二次失败即换方案或放弃 |
| 截图 | **≤ 2 张/条目** | 落地页 1 张 + 结果 1 张，够判断就走 |
| DOM 快照 | **≤ 2 次/条目** | 只用来定位控件；题名/摘要读不到就截图，别反复读 |
| 整批条目数 | **≤ 10 条/批** | 超了拆批，批次之间留 30 秒以上 |

## 2. 四条「已知死法」，必须显式禁止

逐条写进指令，不要指望执行者自己读到 Skill：

1. **反复重试 `tabs_close`**：报 timeout 时页面**通常已关**。规则是"报错就查一次 `tabs_list`，还开着再关一次，仍失败就放着继续下一篇"。
2. **反复截图分析同一页**：2 张封顶。第 3 张不会带来新信息，只会烧时间。
3. **死磕单篇**：某篇下不下来是常态（付费墙/验证码/格式），**跳过它比救活它更有价值**，因为整批交付比单篇完整重要。
4. **在详情页找下载按钮**：知网的下载按钮在**结果页**，不在详情页；ScienceDirect 的 `pdfft` 链接在结果页 href 里。

## 3. 停机条件（整队停止，不许降级硬试）

- CAPTCHA /「Are you a robot?」/ unusual traffic / 403 / 429
- 跳登录页且需要输入账号密码（**绝不代输凭据**）
- Cloudflare / JS challenge 中间页
- 机构名消失且出现 `Get Access` / 购买按钮

出现任一条：**当前平台整队停**，标 `blocked`，写清错误原文，交回主会话。**不换 IP、不换节点、不重放。**

## 4. 代理前置检查（每次派活前主会话做一次）

```bash
# 直连出口（应为国内/机构 IP）
curl -s -m 10 --noproxy '*' "http://ip-api.com/line/?fields=query,country,isp"
# 代理出口（若与上面不同，说明开了代理）
curl -s -m 10 --proxy "http://127.0.0.1:<port>" "http://ip-api.com/line/?fields=query,country,isp"
```

- 目标是**机构订阅库**（Elsevier / Springer / Wiley / 知网 / 万方）→ 必须**直连**；出口 IP 落在境外就先让用户关代理。
- 目标是**公开资源**（GS / PubMed / arXiv）→ 直连不通再用代理。
- 把结论写进指令第一行，执行者不用自己判断。

## 5. 回报 JSON 最小结构

```json
{
  "batch": 1,
  "platform": "cnki",
  "items": [{
    "n": 1, "target": "题名或DOI",
    "status": "ok|not_found|no_access|blocked|failed",
    "saved_filename": "", "file_size_kb": 0,
    "steps": 0, "elapsed_s": 0,
    "error": "", "notes": ""
  }],
  "summary": {
    "ok": 0, "not_found": 0, "no_access": 0, "blocked": 0, "failed": 0,
    "tabs_left": 0, "identity_seen": "",
    "skill_gaps": [{"file": "references/platforms-cn.md", "field": "download", "evidence": "实测", "note": ""}]
  }
}
```

- `saved_filename` 必须是 `ls` 里**真实看到**的名字，`file_size_kb` 用 `stat` 实值。
- `skill_gaps` 只在**真在页面上看到**时才写 `evidence: "实测"`，否则 `未验证`。
- 结束前必须 `tabs_list` 复核并写 `tabs_left`。

## 6. 给主会话的验收清单

执行者回来，主会话按这 6 条验，不通过就打回：

1. 文件数对不对（`ls | wc -l` 与回报条数一致）；
2. 每个文件过魔数 + 尾部闭合（`litadopt.py verify` 或 `oa_fetch.py check`）；
3. 下载目录是否回到基线（若要求"不留"）；
4. 标签页是否清空（`tabs_list`）；
5. 有没有重复副本（MD5 去重）；
6. 命名里的来源名是真期刊名还是知网内部表名（`JCZG…`/`BIGO…` 是后者，要 `--source-map`）。
